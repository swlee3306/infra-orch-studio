# Codex Progress

## 2026-05-05

Mode: conservative budget. Scope intentionally limited to `README.md`, `docs/architecture.md`, `docs/roadmap.md`, `Makefile`, `cmd`, `internal`, `web`, `templates/opentofu`, and `deployments/k8s`.

Current state:
- Environment creation queues an initial `tofu.plan` job.
- Environment update and destroy plan requests are environment-scoped.
- Admin-only approval, apply, and destroy gates are implemented in API routes and surfaced in the web UI.
- Runner is separate from API and claims queued jobs from MySQL before rendering templates and running OpenTofu.
- OpenTofu remains fixed-template plus variable injection through `templates/opentofu/environments/basic` and shared modules.
- Job status and `.infra-orch/logs/*.log` streaming are exposed through the authenticated `/ws` endpoint.
- MySQL is the operational store; SQLite remains test/local support.
- Kubernetes legacy manifests include API, runner, web, MySQL, secrets, and a shared workdir PVC through `deployments/k8s/kustomization.yaml`.

3. Reconcile deployment environment variables with the runtime configuration reference.

## 2026-05-05 MVP code pass

Actual execution blockers found:
1. Job logs were only available through WebSocket tailing, so completed or failed jobs had no simple HTTP/curl inspection path.
2. WebSocket log streaming only derived logs from `workdir` and ignored persisted `log_dir` metadata.
3. Runner-controlled failures could mark jobs failed without leaving a runner error log artifact.
